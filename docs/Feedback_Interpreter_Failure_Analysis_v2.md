# Feedback interpreter case-level failure analysis

The original live report identifies literal disagreements and routing errors. A same-configuration v1 capture provides the actual structured proposals for diagnosing these patterns. Case IDs in this section refer to the frozen gold suite. [Original live report and v1 capture](../benchmarks/feedback/README.md)

| Cases | Evidence observed in the v1 capture | Root cause and targeted correction |
| --- | --- | --- |
| FI-023, FI-028 | A commute rule violation became a negative hybrid preference in FI-023. In FI-028, the onsite days and distance became two separate negative signals. Both proposals correctly reported the hard-rule conflict and routed to approval. | The route depended on the presence of a preference. The model treated facts that establish an existing rule conflict as new preferences. Keep a rule-only conflict in profile-fact review and require a separately expressed reaction for a preference. |
| FI-029, FI-034, FI-046 | A generic commute objection became a distance preference. A vague seniority-fit concern became a profile-fact candidate. The original report also shows that the vague culture objection was routed to approval. | The v1 prompt asked for a focused follow-up, but gave the model no concrete test for an underspecified reason or a checkable profile claim. Require a named driver of the reaction and distinguish a concrete present/past claim from a general sense of fit. |
| FI-035, FI-006, FI-036, FI-038 | FI-035 retained career interest, emitted prospective learning as a preference, and described it as a qualification issue in profile-fact review. FI-006 similarly read willingness to train as interest in training. FI-036 and FI-038 had recognizable claims of missing or prior experience. | The example about a learning opportunity did not distinguish wanting a learning benefit from being willing to learn. Route specific self-asserted skills and experience to profile-fact review. Keep independently stated preferences on any route. |
| FI-024, FI-042, FI-043, FI-049 | A remote-work reaction and a client-work reaction can coexist. A career preference can remain relevant alongside an employer or pay objection, or an unresolved objection to this posting. The v1 capture recovered FI-024's client-work line in the first pass, using a different label. | Review independent clauses before choosing the route. Count supported positive and negative signals separately. Check a suspected missing signal against the structured proposal before classifying it as missing in meaning. |
| FI-022, FI-048 | FI-022 converted conditional willingness to do this job elsewhere into interest in program management as a career. FI-048 concerns objection to sales work referenced in a posting. | A posting describes the offer. The user has to express the preference, and acceptance of this job under a counterfactual gives no general career direction. Keep duty-level evidence and category-level evidence distinct. |
| FI-007, FI-040 | The v1 capture used a narrow core-banking replacement transformation category and an explicit quota-carrying sales category. The original literal downgrade gate flagged these cases. | A label difference can cause an unsupported-downgrade flag. Only equivalent category identifiers and a quote that supports the same category and polarity can clear the canonical safeguard. The classification boundary in FI-007 remains a review item. |
| FI-013, FI-014, FI-026, FI-027, FI-037 | FI-013 attributed a generic reaction to innovation work and emitted a pay preference from a rule. FI-014 inferred a rate objection from a sentence about gaps in billable work. FI-026 treated a rule's ten-mile threshold as a new preference. FI-027 weakened weekly flights to generic frequent travel, and FI-037 weakened Python-heavy daily work to writing Python. | Separate background data, concessions, and qualifiers from preference claims. Keep context qualifiers attached to the signal where they limit the reaction. Preserve mode, frequency, and intensity in a scope when changing them would broaden the preference. |
| FI-050 | The reference asks for evaluation of both rule reconsideration and attraction to an exceptional role. The latter needs an annotation review because the hypothetical identifies no concrete duty. | Evaluate explicit rule reconsideration separately. Hold it for confirmation without altering any rule. Review the role annotation before approving a new gold version. |

These are diagnoses of the observable proposal and prompt behavior. The case-level JSON records every canonical hit, miss, extra signal, and scope disagreement, while the annotation review traces evidence for proposed changes to the references. The automated safeguard flagged this label on both v2 passes. Manual review found support for the narrow category. The recorded flags and scores remain the results of the frozen taxonomy.
